# Memos Sync Plus

将 Memos 单向同步到 Obsidian 的插件。提供库内路径、附件下载和 Sync interval 配置，无需依赖其他社区插件。

## 安装

从 [GitHub Releases](https://github.com/yslemmo/memos-sync-plus/releases/latest) 下载安装包。升级时只替换 `main.js`、`manifest.json` 和 `styles.css`，保留原有 `data.json`。

1. 解压 `memos-sync-plus-1.2.1.zip`。
2. 将其中的 `memos-sync-plus` 文件夹复制到你的库的 `.obsidian/plugins/` 下。
3. 最终结构应为：

   ```text
   你的库/
   └── .obsidian/plugins/memos-sync-plus/
       ├── main.js
       ├── manifest.json
       └── styles.css
   ```

4. 重新加载 Obsidian，在「设置 → 第三方插件／社区插件」中启用 **Memos Sync Plus**。
5. 打开插件设置，填写 Memos 网站根地址和 API 令牌，点击「测试连接」，再点击「立即同步」。

插件 ID 为 `memos-sync-plus`，与两个参考插件不同。尚未发布到社区市场，可手动安装。需要 Obsidian 1.5.0 或以上版本。构建没有 Node.js 运行时依赖，可用于桌面与移动版；移动端尚未做实机测试。

## 配置

| 配置 | 默认值 | 行为 |
| --- | --- | --- |
| Memos 服务器 | 空 | 网站根地址，例如 `https://memos.example.com`，不添加 `/api/v1`；支持反向代理子路径 |
| API 令牌 | 空 | 使用 Memos 设置中的访问令牌；401/403 会明确提示令牌或权限问题 |
| API 类型 | 新版 | `/api/v1/memos`，支持新版 `attachments` 和早期 `resources`；另有旧版 `/api/v1/memo` 选项 |
| 用户资源名 | 自动识别 | 默认通过身份接口识别当前用户；兼容回退到旧版身份接口；可手填 `users/lemmo` 或 `users/1` |
| 保存方式 | 按天汇总 | 日记模式，或每条 Memos 一个文件 |
| File name format（文件名格式） | ID | 独立笔记可选 ID、Created at、Updated at、Title；每种格式都保留 Memos 链接末尾的原始 ID |
| 同步路径 | `Memos` | 库内相对目录，可为 `日记/Memos`；留空表示库根目录；自动创建目录 |
| 跟随日记设置 | 关闭 | 开启后优先读取已启用的 Periodic Notes 日记配置，其次读取核心日记的目录、日期格式与模板 |
| 日记日期格式 | `YYYY-MM-DD` | Moment 格式；支持 `YYYY/MM/YYYY-MM-DD` 这样的多级目录；必须区分年、月、日 |
| 新笔记模板 | 空 | 库内 Markdown 文件，例如 `Templates/Memos.md`；支持 `{{date}}`、`{{time}}`；不执行 Templater 脚本 |
| 自定义正文模板 | 空 | 每条 memo 的受管正文模板；留空使用原样式，非空时覆盖列表／Callout 默认样式；需包含 `{{content}}` |
| 添加笔记属性 | 开启 | 独立笔记添加 `memos_*` 元数据与原生 `tags`，保留自定义字段；日记汇总不添加单条记录属性 |
| 同步历史保留条数 | 50 | 可配置 1–200 条，历史和待重试信息在重启后保留 |
| Memos 区域标题 | `Memos` | 标题不存在时自动创建；无需在日记模板中事先添加标题 |
| 同步最近多少天 | `0` | 0 表示全部；例如 30 包含今天及之前 29 个本地日历日 |
| 展示样式 | 列表时间线 | 另有原生 Callout 样式，不依赖 List Callouts 插件 |
| 显示时间表情 | 开启 | 显示 🌅／☀️／🌆／🌙 |
| 显示来源链接 | 开启 | 链接到 Memos 原始记录 |
| 较新的记录在上方 | 关闭 | 默认从早到晚排列 |
| 下载附件 | 开启 | 下载 API 附件；关闭后保留远程链接 |
| 附件保存路径 | `Memos/attachments` | 文件名包含稳定 ID，避免同名文件覆盖 |
| 单个附件上限 | 50 MB | 下载失败或超过上限时保留远程链接并提示，下次重试 |
| Sync interval | `0` 分钟 | 0 关闭；支持 1–1440 分钟；修改后立即重新计时 |
| 启动后自动同步 | 关闭 | 库加载完成后延迟 5 秒执行 |
| 移除远端已删除／归档的记录 | 关闭 | 开启后移除当前时间范围内、本插件已跟踪的远端缺失记录；保留笔记文件和附件 |
| 本地修改冲突处理 | 跳过并提示 | 可选择备份完整笔记后更新同步区域；备份在同步目录的 `Memos Sync Backups` 下 |

自动同步只在 Obsidian 运行时执行。手机切到后台或电脑休眠期间，不保证定时运行。

## 命令

点击侧边栏同步按钮，或者在命令面板中搜索 `Memos Sync Plus`：

- **立即同步 Memos**：检查所选时间范围内的新增、编辑与附件变更。
- **全量同步所有 Memos**：忽略天数限制，重新核对全部记录，仍然遵守本地冲突处理选项。
- **预览 Memos 同步**：读取远端与本地内容，展示计划，不执行文件写入或附件下载。
- **预览全量 Memos 同步**：预览所有记录，忽略天数限制。
- **查看同步历史**：查看持久保存的同步结果、失败原因和重试入口。
- **重试失败的同步**：重试最近尚未处理的失败项；本地修改冲突仍遵守原设置。
- **同步当前日记的 Memos**：只处理当前日记对应日期；支持日期子目录。
- **测试 Memos 连接**：读取当前用户与可同步记录数量，不写入笔记。
- **查看最近同步结果**：查看更新文件数、附件下载数、本地冲突和失败详情。
- **打开 Memos Sync 设置**。

桌面状态栏显示同步状态，点击可查看详细结果。没有变化的自动同步不会弹出通知；失败和需要处理的情况会提示。

## 同步预览、历史与重试

在设置页「预览与历史」中，可以直接使用 **同步预览**、**同步历史** 和 **失败重试**。

- 预览列出将新增／更新的笔记、改名前后路径、将下载的附件、将移除的受管记录、冲突及备份计划。预览的变更在内存中演算，不创建笔记、附件、目录、备份，不保存同步缓存或历史。
- 预览仍需读取 Memos 的记录列表和本地笔记；不会试下载附件，因此不能提前确认下载网络、证书或文件系统写入权限。点击「执行同步」会重新读取并计算最新内容。
- 历史记录包含开始／结束时间、同步方式、状态、统计与错误详情。默认保留最近 50 条，可在设置中调整；预览不算实际同步历史。
- 附件、笔记写入、重命名或本地冲突失败时，保存对应 memo ID。重试会重新读取完整分页以确认最新数据，但只更新失败的 memo，不重新写入无关记录；同一日记内未重试的记录保留已有缓存正文。
- 整次 API 请求失败时，重跑原本的普通／全量／当前日记范围。定向重试会忽略天数限制，以免失败记录后来移出最近几天的窗口。
- 重试检查历史所对应的服务器、保存方式、目录和实际 Memos 用户，防止把旧失败任务重试到其他账户或目录。切换配置后应先恢复对应配置再重试。
- 普通同步成功修复失败项后，它们也会标为「已处理」；原历史结果与错误仍然保留。待重试项只随保留的历史保存，较旧历史被移出保留范围后无法从该历史发起重试，可执行正常同步重新核对。
- 历史保存文件路径、ID、统计和错误，不额外复制 Memos 正文或 API 令牌；仍应将插件 `data.json` 作为私有数据保存。

## 独立笔记属性

开启「添加笔记属性」后，独立笔记顶部会加入原生 YAML 属性：

```yaml
---
memos_id: 原始ID
memos_created: "2026-10-13T04:00:00.000Z"
memos_updated: "2026-10-14T03:26:24.000Z"
memos_source: https://memos.example.com/memos/原始ID
memos_creator: users/用户名
tags:
  - 健康/运动
---
```

同步会更新这些 `memos_*` 字段，合并 Memos API 返回的标签到原生 `tags`；现有自定义字段与标签保留，不自动删除本地标签。YAML 可能重新格式化，属性值会保留。关闭此开关后，不继续更新属性，也不移除已经写入的属性。

受管 `memos_*` 字段被本地修改时，默认跳过并提示；可按原设置备份后更新。原有 YAML 格式损坏时不覆盖，需修复后再重试。日记汇总文件中包含多条 memo，因此不写入单条记录属性。

## 自定义正文模板

「新笔记模板」负责新文件初始内容；「自定义正文模板」负责每次同步的单条 Memos 正文，两者可以同时使用。正文模板非空时，不再套用原列表／Callout 样式，也不会额外添加原底部时间。

| 占位符 | 内容 |
| --- | --- |
| `{{content}}` | Memos 正文，必需；已处理附件引用 |
| `{{attachments}}` | 将全部 API 附件单独放在该位置；已从正文移除这些附件的原引用 |
| `{{id}}` | Memos 链接末尾的原始 ID |
| `{{title}}` | API 标题或正文第一行提取的标题 |
| `{{date}}` | 设备本地创建日期，`YYYY-MM-DD` |
| `{{time}}` | 设备本地创建时间，`HH:mm` |
| `{{emoji}}` | 时间表情，受显示时间表情开关控制 |
| `{{created}}` / `{{updated}}` | ISO 创建／更新时间 |
| `{{source}}` | Markdown 来源链接，受来源链接开关控制 |
| `{{source_url}}` | 原始 Memos 链接 URL |
| `{{tags}}` | API 标签，格式为 `#标签` |

只显示正文和附件，可使用设置页的「使用简洁模板」按钮：

```text
{{content}}

{{attachments}}
```

显示时间、来源和单独附件区域：

```text
# {{emoji}} {{time}} {{source}}

{{content}}

## 附件

{{attachments}}
```

日记列表可以使用：

```text
- **{{emoji}} {{time}}** {{source}}
  {{content}}
  {{attachments}}
```

多行正文在缩进或引用块位置会延续该行缩进。模板不包含 `{{attachments}}` 时，附件仍保留在 `{{content}}` 中，不会被遗漏。模板只替换已知变量，不执行 JavaScript 或 Templater，也不二次解释远端正文中的占位符。留空或点击「恢复默认正文」可恢复旧版样式。

## 保存格式

默认写入 `Memos/2026-10-13.md`：

```markdown
## Memos

<!-- memos-sync:实例标识:start -->
- **🌅 08:30** [来源](https://memos.example.com/memos/记录ID)
  今日想法 #生活

- **☀️ 14:20** [来源](https://memos.example.com/memos/另一条记录ID)
  - [ ] 待办事项
  ![[Memos/attachments/带ID的图片.png]]
<!-- memos-sync:实例标识:end -->

## 本地补充

这里的内容在同步时保持原样。
```

正文中的标签、任务列表、标题、链接和代码块保留 Markdown 结构。创建时间相同的 Memos 仍然按独立 ID 保存，不会互相覆盖。

### 独立笔记文件名

选择「每条 Memos 独立笔记」后，设置中会显示 **File name format（文件名格式）** 下拉菜单：

| 选项 | 示例 |
| --- | --- |
| ID（默认） | `2026-10-13 XX8aHdgPnV9ioFYrW6yt78.md` |
| Created at（创建时间） | `2026-10-13 21-22-02 XX8aHdgPnV9ioFYrW6yt78.md` |
| Updated at（更新时间） | `2026-10-14 11-26-24 XX8aHdgPnV9ioFYrW6yt78.md` |
| Title（标题） | `2026-10-13 今日感想 XX8aHdgPnV9ioFYrW6yt78.md` |

`XX8aHdgPnV9ioFYrW6yt78` 是 Memos 链接 `/memos/XX8aHdgPnV9ioFYrW6yt78` 末尾的原始 ID，不再使用哈希值。旧版接口如同时提供数字资源名和 `uid`，文件名使用链接对应的 `uid`，同步缓存仍以 API 资源名识别。

四种格式都保留原始 ID，以免同一天、同一秒或相同标题覆盖。日期和时间按设备本地时区计算；标题模式优先使用 API 的标题，缺失时取正文第一行并去除常见 Markdown 标记，空正文退回日期 + ID。非法文件名字符会转换，较长标题会截断。

切换格式、修改标题或更新 Memos 的更新时间时，本插件通过 Obsidian FileManager 重命名已跟踪笔记，保留整篇笔记并更新本地反向链接；目标文件已存在时跳过并提示，不覆盖已有文件。默认冲突策略也适用于重命名。

从 1.0.0 升级：停用插件，仅替换 `main.js`、`manifest.json` 和 `styles.css`，保留原有 `data.json`，再重新启用。下次同步自动将已跟踪的独立笔记从「日期 + 哈希」迁移为所选格式，不留下空的旧文件。设置了天数限制时，仅迁移本次范围内的记录；执行「全量同步所有 Memos」可迁移全部已跟踪记录。日记汇总模式的日期文件名不受影响。

## 同步与数据保护

- **方向**：Memos → Obsidian。不向 Memos 写入，不支持双向同步。
- **更新检查**：每次读取当前用户所有正常记录的完整分页，在本地应用日期限制、比较内容并只写入有变化的文件。这保证旧记录被编辑时也会被发现，但网络读取并非仅获取上次同步以来的数据；大量历史记录会增加请求开销。
- **分页失败**：任何分页失败、异常响应或重复分页标记都会停止本次同步，不将不完整结果当作删除依据。
- **本地内容**：更新本插件 `memos-sync` HTML 标记内的正文，以及开启笔记属性时的受管 `memos_*` 字段和标签合并。其他本地正文和自定义属性保留。本地修改受管内容时默认跳过并提示；同步标记损坏不会自动修复或覆盖。
- **删除**：默认保留本地已同步记录。开启删除联动后，远端删除、归档或不再属于选定范围的记录才会从当前同步区域移除。超出天数范围的历史文件不会因此被清空。
- **附件**：只下载 Memos API 附件，不抓取正文中任意网站的图片。已下载的文件重复同步时复用，不会自动清理孤立附件。关闭下载也不会删除已有附件。
- **附件改名兼容**：附件路径会登记到缓存，创建后与写入笔记前均核对实际路径。兼容 Paste Image Rename 的自动改名；后续改名事件会更新路径与缓存引用。旧版缓存缺少路径登记时，若预定文件名不存在，会下载源附件以逐字节比对附件目录中已有文件，找到相同内容后复用，不依据相同文件大小或文件名猜测图片。这样可以修复已改名图片的旧引用而不重复创建图片。
- **图片短地址**：正文中的 `/file/attachments/ID` 和 `/file/attachments/ID/文件名` 都按附件 ID 替换为本地引用，不重复追加图片。下载关闭或失败时替换为完整的远程 URL，防止 Obsidian 将服务器相对路径误认为库内文件。无关链接及代码示例保留原样。
- **下载上限**：优先检查 API 返回的大小，再校验下载后的实际大小；Obsidian 的 `requestUrl` 不提供流式下载，API 未提供准确大小时，大文件仍可能在校验前进入内存。
- **凭据**：API 令牌以明文保存在本库的 `.obsidian/plugins/memos-sync-plus/data.json`，该文件还保存同步缓存正文和状态。不要将其上传公开仓库。插件不把令牌写入 Markdown、文件名、请求 URL 或日志。外部附件请求不附带 Memos Bearer 令牌。
- **缓存中断恢复**：已写入但缓存未保存的相同内容可在下次同步自动确认；不同内容按冲突策略处理，不自动覆盖。

如果已经使用其他 Memos 插件向相同日记写入内容，建议关闭其自动同步，再使用本插件，避免两个插件同时维护同一个区域。其他插件已写入的内容不会自动迁移成此插件的受管区域。

## 兼容性与验证

重点按 Memos v0.30 的 `attachments`、`creator`、`createTime`、`updateTime` 字段实现；兼容早期 `resources`、`resourceList` 与秒级时间字段。旧版 API 为显式选项，不在认证失败时自动切换，避免掩盖真实错误。

**已验证**：116 项自动化测试，包括自动附件改名、延迟改名、同大小不同内容的图片比对、旧缓存路径恢复、后续改名缓存跟踪、只读预览、历史、定向重试、属性、模板及原有同步功能；TypeScript 检查与生产构建通过。

**验证边界**：已根据实际同步笔记、附件目录及 Paste Image Rename 配置确认短地址与附件改名这两类原因。1.2.1 的改名兼容运行测试使用隔离的 API／DOM 环境，真实 Obsidian 环境中的新逻辑尚待重载后核验；未对所有历史 Memos 版本与移动设备逐一实测。

## 升级后修复已有图片笔记

1. 停用插件，用 1.2.1 的 `main.js`、`manifest.json`、`styles.css` 替换旧文件，保留 `data.json`。
2. 重新启用插件，执行「全量同步所有 Memos」。
3. 旧版本留下的「服务器短路径图片 + 本地图片」会更新为一个有效本地图片引用；已下载的附件直接复用，不必删除后重下。
4. 如果使用附件自动重命名插件，1.2.1 会记录改名后的实际路径。已有图片文件被改名但缓存保留旧名字时，会按源内容找回旧图片并更新引用。

如果同步区域有手动修改，仍会遵守原有冲突设置，默认跳过并提示；同步区域外的本地内容保持原样。

## 开发

需要 Node.js 20.11 或以上版本；打包命令还需要 Python 3（命令名 `python3`）：

```sh
npm ci
npm test
npm run build
npm run package
```

`npm run dev` 监听源码变更并重新构建。Obsidian 加载 `main.js`、`manifest.json` 和 `styles.css` 即可。

源码布局：`client.ts` 处理接口，`filename.ts` 处理文件名，`attachments.ts` 匹配图片引用，`properties.ts` 合并属性，`preview.ts` 提供只读演算，`sync.ts` 处理同步与失败记录，`render.ts` 维护正文和变量模板，`main.ts` 接入设置、历史、重试、命令和定时任务。测试不会访问个人笔记或真实 Memos。
